The key idea of a sequence CRDT like Yjs: instead of “insert at position 5”, which breaks as soon as someone else edits before position 5, every inserted item gets a globally unique ID — the client’s ID plus a counter — and records which item it was inserted after. When two clients insert at the same spot, a deterministic tie-break on client ID orders them identically everywhere. Deletes leave tombstones so late-arriving inserts can still find their anchor. The merge is commutative, associative and idempotent: updates can arrive in any order, be grouped any way, even be delivered twice, and every replica ends up with the same document. That property is also what makes my persistence layer safe, as we’ll see.
