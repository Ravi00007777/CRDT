Collaboration flow

From opening a link to live cursors

1

Connect. Browser opens /collab; the session cookie rides on the upgrade.

2

Authorise. Foreign origins refused; cookie and per-document access checked.

3

Load. Saved state comes from Postgres before any client syncs.

4

Sync. State vectors are exchanged; each side sends only what the other lacks.

5

Edit. Each keystroke becomes a small Yjs update, broadcast to the room.

6

Presence. Names, colours and cursors travel as awareness; dropped on disconnect.

7

Walk through what happens when someone opens a document link. One: the browser opens a WebSocket on /collab; because the dev server proxies it on the same origin, the httpOnly cookie is sent automatically — no token in the URL. Two: the server rejects connections from other origins, then verifies the cookie and checks this user’s access to this specific document. Three: the document is loaded from Postgres before anyone syncs, so a client never sees an empty doc that later gets overwritten. Four: the Yjs sync protocol exchanges state vectors — compact summaries of what each side has — so a reconnecting client only transfers the difference. Five: every edit is a small incremental update, never the whole text. Six: presence — names, colours and cursor positions — travels on a separate awareness channel and disappears when a socket closes.
